# Time Gal — заметки для tgvplay

Документ для проекта `tgvplay`: что делает игра при старте, формат FMV-потока,
карта памяти. Источник: `kapps/TimeGal` (GAL5EVO + NedoOS glue), сборка sjasm.

---

## 1. Карта памяти timegal.com

| Область | Адрес | Содержимое |
|---------|-------|------------|
| Точка входа | `#0100` | `LD SP,#3FF0` — сигнатура «наш .com» |
| Glue (I/O, FMV) | `#0100`–`#1929` | Код и данные NedoOS-прослойки |
| **Дыра (padding)** | `#1929`–`#5FFF` | **Нули в .com, кода нет** |
| GAL5EVO | `#6000`–`~#C4D8` | Оригинальный движок игры |
| `GO` | `#6792` | Главная инициализация |
| `WASLOA` / `loa` | `#6000` → `#9E4A` | Встроенный блок `loa16` (1923 байта) |
| `TFILES` | `#84CC` | Каталог 202 файлов × 8 байт |
| `tg_secbuf` | `#015D` | Буфер сектора 2048 байт |
| Экран FMV | `#4000` / `#8000` | User screen (double buffer) |

**Важно:** адрес **`#5271` попадает в дыру `#1929–#5FFF`**. В файле там `00 00 00…`
(NOP). Если PC оказывается там — это **сбой** (порча стека / неверный return),
а не «код игры». При неверной странице `#0000` вместо NOP там может быть мусор
и «кручение» в районе `#5271`.

## 2. Старт игры: от .com до первого кадра FMV

### Блок A — NedoOS entry (`#0100`, `timegal.asm`)

| Шаг | Действие | Зачем | Результат |
|-----|----------|-------|-----------|
| A1 | `LD SP,#3FF0`, `DI` | Стек, без прерываний | SP=`#3FF0` |
| A2 | `OS_HIDEFROMPARENT` | Скрыть от родителя | — |
| A3 | `OS_SETGFX` + `OS_CLS` | Графический режим, чистый экран | — |
| A4 | `TG_GFX_INIT` | Страницы памяти, палитра, `OS_NEWPAGE` ×7 | `tpgs[]`, `pgmain*` |
| A5 | `TG_OS_BOOT` | `OS_CHDIR` → `Tg/timegal` или `timegal` | `tg_chdir_ok` |
| A6 | `JP GO` | Передача в GAL5EVO | A=`#A0`, E=Covox port |

**Диск:** только смена каталога, **без чтения файлов**.

---

### Блок B — `GO` (`GAL5EVO.asm`, `#6792`)

| Шаг | Действие | Зачем | Куда |
|-----|----------|-------|------|
| B1 | `LD SP,#3FF0` | Стек снова | — |
| B2 | `OUT7FFD #10` | Legacy → **`TG_SETMAIN`** | Main pages |
| B3 | `LDIR WASLOA→loa` | Развернуть **`loa16`** из .com | `#6000`→`#9E4A` |
| B4 | `CLSATM` | Очистка user screen | `#4000`/`#8000` |
| B5 | **`TG_INIT`** | Построить LBA-таблицу | `TFILES`, `TG_NAMETAB` |
| B6 | **`MKTY`** | Таблица адресов строк экрана | `tg_ty` (`#09CF`) |
| B7 | Mute AY | Заглушить звук | порты AY |
| B8 | **`NEWVIDEO`** | Старт intro FMV | см. ниже |
| B9 | `JP TG_VIDEO_TICK` | Видео-цикл | glue FMV |

#### B5 — `TG_INIT` (≈8 секунд на SD)

Для **каждой** из **202** записей `TFILES`:

1. Имя 4 символа (Motorola CD: `GINT`, `LEV1`, …) → `TG_NAMETAB`
2. Записать накопленный LBA в `TFILES+0..3`
3. `TG_MAPNAME`: `GINT` → имя файла **`gintro`**
4. **`OS_GETFILINFO`** по пути — **только размер**, файл **не открывается**
5. Размер → число секторов (ceil/2048), прибавить к `tg_cum_lba`

**Это и есть «~8 секунд что-то читает с диска»** — не FMV, а **202 stat-запроса**
по всему каталогу уровней/death-сцен/movie-events.

#### B8 — `NEWVIDEO`

| Поле | Значение |
|------|----------|
| `SECTOR` | 0 (из записи `fINTRO` / `GINT`) |
| `CUREVENT` | `SCRIPTINTRO` (скрипт intro) |
| `CURENDOFVIDEO` | следующий файл (`fL1`) |
| `LASTSND` | Заполнить `#80` × 2048 (заглушка звука) |
| `TG_COPY_FMVDATA` | `SECTOR` → `tg_sector` |
| **`READ_P1`** | Пропуск padding-сектора 0 (**без чтения**) |

---

### Блок C — `TG_VIDEO_TICK` (первый кадр)

| Шаг | Действие | Диск | Результат |
|-----|----------|------|-----------|
| C1 | `TG_CLEAR_USER_SCR` | — | Экран `#4000`/`#8000` = 0 |
| C2 | `TG_COPY_FMVDATA` | — | `tg_sector` обновлён |
| C3 | `TG_SET_FMVPAL` | — | 16-цветная палитра FMV |
| C4 | **`TG_OPEN_GINTRO`** | **OPEN** `gintro` | `tg_handle`, seek→сектор 1 |
| C5 | `TG_SECTLOOP` | **READ 2048** | `tg_secbuf` |
| C6 | `TG_FRAMELOOP` ×113 | — | Декод кадров |
| C7 | **`TG_NEWPLQ`** | — | **Первый видимый кадр** на экране |

---

### Сводка дисковых операций ДО первого кадра

| Операция | Кол-во | Файл | Данные |
|----------|--------|------|--------|
| `OS_CHDIR` | 1–2 | каталог | — |
| `OS_GETFILINFO` | **202** | все файлы каталога | только size/stat |
| `OS_OPENHANDLE` | 1 | **`gintro`** | handle |
| `OS_READHANDLE` | 1 | **`gintro` сектор 1** | **2048 байт** → `tg_secbuf` |

`loa16` — **внутри .com**, с диска не читается.

## 3. Формат FMV-потока (файл `gintro`)

### 3.1. Уровень файла

| Параметр | Значение |
|----------|----------|
| Размер сектора | **2048 байт** |
| Сектор 0 | **2048 × `0x80`** — padding, **пропускается** |
| Сектор 1+ | Реальные FMV-данные |
| Секторов за проход | **8** (`sectcycl=8`), затем новый `TG_VIDEO_TICK` |
| Кадров на сектор | **113** слотов |
| Хвост сектора | **7 байт** читаются и отбрасываются после 113 слотов |

### 3.2. Слот кадра (113 раз на сектор)

```
byte0 — управляющий:
        bit7=1 → NEWPLANE (смена экранной страницы / EOF)
        bit7=0 → обычный кадр → NEWPLQ

byte1 — часть адреса (индекс строки: byte0 & 31 → tg_ty)
        + byte1 → 16-bit адрес в экране (#4000-based)

Если H >= #40 → рисуем кадр:
        8 полос × (1 байт пиксель + шаг DE=39)
        SET 5,H → атрибутная половина (+#0800)
        ещё 8 полос × 1 байт атрибут
        Итого: 2 + 16 = 18 байт на нарисованный кадр

Если H < #40 → skip (только 2 байта заголовка, без blit)
```

### 3.3. Управляющие символы (bit7=1)

| Младшие 7 бит | В файле | Смысл |
|---------------|---------|-------|
| `#0A` | **`#8A`** | **Конец видео** → `TG_ENDOFVIDEO` |
| другое | `#8X` | NEWPLANE — переключить `#7FFD`-страницу (`#13`/`#17`) |

### 3.4. Padding `0x80`

- Сектор 0 файла = сплошные `0x80`
- Начальное заполнение `LASTSND` (`#B500`) — тоже `0x80`
- **Не** opcode кадра; просто filler

### 3.5. Схема потока (высокий уровень)

```
[Сектор 0: 2048×0x80 — SKIP]

[Сектор 1..N: по 2048 байт]
  repeat 8 секторов за цикл видео:
    repeat 113 слотов:
      ctrl byte:
        0xxxxxxx → кадр (2 или 18 байт)
        1xxxxxxx → NEWPLANE или EOF (#8A)
    + 7 байт хвоста
    show plane, next sector
```

### 3.6. Чтение в NedoOS-порте

| GAL5EVO | NedoOS glue |
|---------|-------------|
| `READCD` | `TG_LOAD_SECTOR` (seek+read 2048 в `tg_secbuf`) |
| `READ_P1` | `TG_SKIP_PAD_SECTOR` (сектор 0 → сектор 1) |
| `READ_P2` | 4× `TG_READ_S` (512 байт) |
| `READ_S` | 512 байт из `tg_secbuf` через `TG_GETBYTE` |

Звук в порте отключён (`nosound=1`).

## 8. Звук в FMV-потоке (для tgvplay ? заготовка)

### 8.1. Откуда берутся данные

В оригинале GAL5EVO на каждый сектор видео (`READCD`, 2048 байт) параллельно вызывается **`READ_P2`**: четыре раза **`READ_S`** по **512 байт** ? **2048 байт** в буфер **`LASTSND`** (`#B500`, `SNDLEN=2048`).

В NedoOS-glue (`timegal_io.asm`) `READ_S` читает **из того же потока**, что и видео: `TG_GETBYTE` ? `tg_secbuf` / следующий сектор. Звук и видео **перемежаются в одном байтовом потоке**; при `nosound=1` байты звука не потребляются во время decode.

Перед стартом intro `NEWVIDEO` заполняет `LASTSND` байтами **`0x80`** (тишина / filler, как padding сектора 0).

### 8.2. Воспроизведение (оригинал, ATM)

В **`SNDLOOP`** / цикле **`SECTLOOP`** во время декода кадра:

- Буфер **`LASTSND`** (2048 байт) ? сэмплы для **Covox** (порт задаётся при старте, ATM: `#FB`).
- Между половинами blit кадра ? **`OUTI`** в Covox (макрос с `pause` для тайминга).
- Параллельно опрос IDE/`hddstat` подкачивает следующие 512-байтные куски в хвост буфера (`RDSND0`, `sldoigr`).
- Указатель в буфере сравнивается с `LASTSND+SNDLEN-1`; при достижении конца ? **`READ_P2`** подгружает следующие 2048 байт с диска/CD.

AY8910 при старте intro заглушается (`GO` ? `SHUT0`); FMV intro в основном **Covox 8-bit mono**, не PT3.

### 8.3. Что делает tgvplay сейчас

| Компонент | Статус |
|-----------|--------|
| Буфер `sndbuf[2048]` в `fmv.c` | есть (аналог `LASTSND`) |
| Чтение `READ_P2` из потока | **не включено** ? сначала видео на экран |
| `OS_PLAYCOVOX` / `output()` на Covox | **позже**, после стабильного видео |
| Подгонка таймингов звука | **не в приоритете** |

План: после заставки TG добавить потребление 2048 звуковых байт на сектор (как `READ_P2`) и вывод через `OS_PLAYCOVOX_PLAY` или `output(covox_port)` между кадрами ? с синхронизацией по `YIELD`/таймеру.

## 4. Каталог TFILES (202 файла)

Запись 8 байт:

```
+0..3  LBA (LE, абсолютный в «диске» каталога)
+4..5  DW script (указатель на сценарий)
+6..7  DW next (следующий файл в цепочке)
```

Первый ролик: **`GINT`** → файл **`gintro`**, LBA=0, script=`SCRIPTINTRO`.

Остальное: `lev1`…`levg`, `mev1`…, death-сцены `l1d1`… — для игры,
**не для intro FMV**.

---

## 5. План для tgvplay (C)

Минимальный плеер без GAL5EVO:

1. `OS_CHDIR` → каталог с `gintro`
2. `OS_OPENHANDLE` → `gintro`
3. Seek сектор 1 (пропуск `0x80` padding)
4. Цикл: read 2048 → decode 113 slots → blit на `#4000`
5. NEWPLANE / `#8A` по правилам выше

Не нужны: `TG_INIT` (202 GETFILINFO), TFILES, `loa`, AY, Covox.

---

## 6. Полный порядок (краткая блок-схема)

```
#0100 entry
  → TG_GFX_INIT
  → TG_OS_BOOT (chdir)
  → GO
      → LDIR loa (из .com)
      → TG_INIT (202× GETFILINFO)     ← «8 секунд диска»
      → MKTY (tg_ty)
      → NEWVIDEO (SECTOR=0, LASTSND=#80)
      → READ_P1 (skip sector 0)
      → TG_VIDEO_TICK
          → OPEN gintro
          → LOAD sector 1 (2048 bytes)
          → FRAMELOOP → NEWPLQ (1-й кадр)
```
