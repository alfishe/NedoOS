# prep-tgv.ps1

Готовит ролик для конвертера Video Converter for ZX Spectrum (режим 16col) и плеера tgvplay.

На выходе кадры BMP 256?192 и звук WAV 44 кГц, стерео, 16 бит. Лишние кадры выкидываются здесь, в конвертере шаг остаётся 1.

## Что нужно

ffmpeg. Если его нет:

```
winget install Gyan.FFmpeg
```

После установки открой новое окно PowerShell. Скрипт ищет ffmpeg сам: в PATH и в папке WinGet.

## Запуск

Из папки `src\kapps\tgvplay`:

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\prep-tgv.ps1 .\MyVideos
```

Один файл:

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\prep-tgv.ps1 .\MyVideos\clip.mp4
```

Папка с несколькими роликами обрабатывается целиком. Рядом с каждым роликом появляется своя папка.

Полезные ключи:

| ключ | зачем | по умолчанию |
|---|---|---|
| `-Fps 15` | сколько кадров в секунду записать | 15 |
| `-Mode crop` | заполнить 256?192, лишнее по краям обрезать | crop |
| `-Mode fit` | вписать кадр целиком, по краям чёрные поля | |
| `-Start 20` | начать с 20-й секунды | 0 |
| `-Duration 30` | взять только 30 секунд | весь ролик |
| `-Digits 5` | сколько цифр в имени кадра | 5 |
| `-OutDir D:\out` | куда сложить результат | рядом с роликом |

Примеры:

```
.\prep-tgv.ps1 .\clip.mp4 -Fps 10
.\prep-tgv.ps1 .\clip.mp4 -Mode fit -Start 12 -Duration 40
```

`-Fps 10` реже кадры и больше знакомест на кадр. `-Mode fit` не режет лица у широкого кадра.

## Что появляется на диске

Для `NRKTK - Puma.mp4` при `-Digits 5`:

```
MyVideos\nrktk-puma\
  nrktk-puma00000.bmp
  nrktk-puma00001.bmp
  ...
  nrktk-puma.wav
  prep.txt
```

`prep.txt` содержит путь, число кадров и число знакомест. Его и копируй в конвертер.

## Настройки конвертера

Галочка **16col** включена. Без неё получится другой формат, tgvplay его не играет.

Путь вставляется без `.bmp` и без номера кадра. Для Пумы это

```
C:\TEMP\NOS\src\kapps\tgvplay\MyVideos\nrktk-puma\nrktk-puma
```

Кнопка **Apply** сама подставит `.wav`.

Дальше:

| поле | значение |
|---|---|
| маленькое поле слева от 1st frame | столько же цифр, сколько `-Digits`. По умолчанию **5**. Если там 4, конвертер ищет `0000.bmp` и сразу выходит с нулями |
| 1st frame | 0 |
| last frame | на 1 меньше числа кадров из prep.txt. 9999 тоже можно: конвертер остановится, когда кадры кончатся |
| frame step | 1. Кадры уже прорежены скриптом |
| поле 225 | число знакомест на кадр, из prep.txt |

Сколько знакомест ставить при своём `-Fps`:

| -Fps | знакомест на кадр |
|---|---|
| 10 | 338 |
| 15 | 225 |
| 20 | 169 |
| 24 | 141 |
| 25 | 135 |
| 30 | 113 |

satu, brig, cont, R, G, B и нижние пороги ошибок можно не трогать, пока картинка устраивает. **Bright** и **dith** при включённом 16col почти ни на что не влияют.

Если конвертер мгновенно пишет `conversiontime=0` и все `holesstat=0`, он не открыл первый кадр. Проверь путь и число цифр.
